# 可安装版本部署

当前版本是单站点部署：一个域名承载一条可编辑行程及其账本。管理员在后台编辑行程、成员、访问码、管理员账号、地图和 AI 设置；旅伴通过访问码进入，再点选身份记账。它适合为不同客户分别部署独立实例，尚未实现一个实例中管理多个客户、订阅计费或租户隔离。

## 环境

- Node.js 24 或更新版本、PostgreSQL 14 或更新版本。
- 一个独立数据库和数据库用户。不同实例不要共用数据库，除非明确要迁移同一份账本。
- 首次安装时在 `/install` 填写数据库连接信息。应用将连接保存到不公开的 `data/database.json`，并在安装成功后生成 `data/install.lock`；部署时需持久化整个 `data/` 目录。旧站点仍可使用已有的 `DATABASE_URL` 环境变量。
- 高德 Web 端 JSAPI Key 需允许部署域名，HTTPS 是手机定位的前提。

## 首次安装

1. 创建独立数据库和账号，在项目目录运行 `npm ci` 和 `npm run build`。
2. 启动 `npm start`，将域名反向代理到 `PORT`（默认 4173）。
3. 打开 `https://你的域名/install`，填写 PostgreSQL 地址、端口、库名、账号和密码，设置行程名称、旅伴访问码、管理员用户名和至少 8 位管理员密码；可选示例行程。
4. 安装成功后，访问 `/admin` 用用户名和密码登录，并配置高德 Web JS API、AI 接口地址/API Key/模型。模型列表可从服务商 `/models` 接口获取，也可手填。每日路段起终点通过高德地点搜索选择。旅伴访问根路径 `/`。

安装仅允许一次，重复 POST `/api/install` 会返回 409。安装锁和数据库安装记录共同阻止重复安装；访问码和管理员密码以加盐 scrypt 摘要保存。`data/database.json` 含数据库密码，不要放入公开目录或提交到 Git；升级部署时连同 `data/install.lock` 一起保留。迁移已有实例时，先备份并恢复数据库；已安装数据库不需要重新初始化。设置 `TRIP_ID` 为原实例的账本标识（可在原配置或数据库的 `trip_expenses.trip_id` 中确认），新实例默认为 `default`。原有账本付款人 ID 必须保留，迁移后请核对成员和费用。后台更改成员名单或默认份数前，系统会把历史全员分摊的份数固定在对应账目上，防止旧结算被重新分配。

`/api/health` 可检查服务和数据库。更新程序时先备份数据库，部署新构建并重启 Node；行程修改无需重新构建。不要把 `.env`、数据库备份或管理员密码放入公开目录。

## 当前边界

成员入口使用轻量身份切换，持有访问码的人可以选任意成员。管理员后台使用独立用户名和密码；旧站升级后用户名默认为 `admin`，原密码不变。付款人可新增、修改和删除自己的费用；后台可查看费用操作记录。登录与安装接口有进程内限流，但多实例之间不共享限流状态或会话。当前没有审批、支付、发票、账号找回和多租户管理。正式销售给互不认识的客户前，需补这些能力和运营支持。
