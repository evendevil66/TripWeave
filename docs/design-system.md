# 出行计划前端设计规范

> Design read：面向自驾旅伴的移动端行程工具，采用安静、耐看的旅行手账语言，强调快速扫描和在路上的单手操作；管理员使用同一视觉语言编辑内容。

## 设计参数

- **设计系统**：自有 CSS token，不引入视觉组件库。页面是行程工具，不是营销页。
- **设计变化**：5/10。保留日期导航和大标题的个性，使用一致的信息结构，方便每天快速查看。
- **动效强度**：2/10。只使用原生 hover/focus 反馈，不做自动轮播和持续动画。
- **信息密度**：5/10。每天一屏优先展示路线、途中安排、住宿和地图入口。

## 色彩

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ink` | `#1B2926` | 正文、标题、主要控件 |
| `--muted` | `#718078` | 辅助信息、地址、说明 |
| `--line` | `#D9D8CC` | 分隔线、输入框、次级按钮 |
| `--paper` | `#FBFAF6` | 当日行程内容面 |
| `--accent` | `#C95C3D` | 日期、重要节点、价格、警示 |
| `--green` | `#365A4D` | 路线、主操作按钮、已完成语义 |
| 页面底色 | `#F6F2EA` | 统一页面背景 |

整页只使用浅色主题。橙红色只表示需要注意的节点，绿色只表示路线或主要操作，避免同色系渐变和装饰性高光。

## 字体与层级

- 正文使用系统中文无衬线字体，保证 iOS、Android、Windows 都能直接渲染。
- 日期、价格、英文小标签使用系统等宽字体，强化可扫读性。
- 页面标题 46–86px，行程标题 23–33px，住宿名称 17px，正文 13–14px，辅助信息 11–12px。
- 标题行高约 1.0–1.2，正文行高约 1.7–1.8；不使用负字距。

## 布局与组件

- 页面最大宽度 720px，手机左右内边距 18px，宽屏内边距 34px。
- 卡片只用于“当天行程”和“住宿/返程硬节点”，不在卡片中继续嵌套卡片。
- 日期导航按后台设置的天数响应式排列，激活态使用底部 2px 橙红色线，不使用胶囊式日期按钮。
- 主要操作按钮为深绿色实底，地图次级操作为描边按钮，复制地址保持最低视觉权重。
- 每天的“途中安排”统一使用：类型标签、区域/景点标题、最多两行说明。
- 文案优先使用区域而非虚构具体店名，例如“途中服务区”“目的地县城”。

## 状态与交互

- 定位状态：`获取位置`、`定位中`、`已定位`、失败提示。
- 费用状态：已知金额显示两位小数，尚未确认的房型或费用显示“待补充”。
- 地图策略：默认在站内显示每天的预设驾车路线和路况图层；定位成功后逐段切换为当前位置起点。同一天的多段路线分别展示，不合并用时。
- `/install` 仅用于首次初始化；`/admin` 使用独立管理员密码，编辑行程、日期、路段、成员与访问设置。表单错误显示在保存操作旁，保存后明确反馈。
- 独立访问码页和用户选择页沿用行程字号、颜色与留白；顶部提供切换身份和退出。
- 验证页不出现具体目的地或完整路线；访问码使用明文输入。成员名称和份数由后台配置，登录后直接点选身份。
- 每次打开路线立即查询高德；地图下方路况汇总标明查询时间，并明确数据覆盖程度。备选路线使用可点选的等宽网格。
- AI 区域先显示缓存建议和上次更新时间，再异步分析高德新数据；更新中或失败时保留缓存，标明它依据的数据时间。不得把 AI 文字当作独立实时数据来源。
- 账本的开支类型使用二选一分段控件，默认共同开支；出发前准备是明确的费用类别。
- 备注输入框先保存到 `localStorage`，通过访问码与身份选择后同步到 PostgreSQL。
- 后台修改成员名单或默认份数时，历史全员分摊账目固定原份数；已有账目引用的成员不能删除。
- 顶部费用概览的“已知共同开支”来自账本，不再独立累加静态住宿价格；个人开支不参与 AA。
- 所有按钮保持原生键盘焦点，`prefers-reduced-motion` 下不使用过渡动画。

## 移动端验收

- 320px 宽度下首屏不出现横向滚动，日期仍可单手点击。
- 有换乘安排的返程日必须可见出发、用餐、进站和发车节点；拥堵延误时调整用餐地点。
- 住宿地址、价格和地图操作在当日内容面内连续出现，不依赖悬浮层。
- 任何路线建议都要标明“可选”或“视路况”，避免把国庆节拥堵当成固定时长。
